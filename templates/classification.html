Classification model

Given information available at the moment the shipping-mode decision is made, what is the probability that this order will be delivered late?

Predictor availability and data leakage

Three columns in this dataset reconstruct the target almost perfectly, and all three are excluded. Delivery Status equals the target exactly on 100% of rows; Days for shipping (real) compared against the promise reproduces it on 97.6%; shipping date (DateOrders) recovers realised transit when differenced against the order date. Including any of them produces the ~99% accuracy commonly reported for this dataset — a number that scores the outcome against itself rather than forecasting anything.

A fourth needs separate handling. Days for shipment (scheduled) is known at decision time, but it is a deterministic lookup on Shipping Mode (Same Day→0, First Class→1, Second Class→2, Standard Class→4), so the two are perfectly collinear. It is kept in the statistical model to demonstrate the multicollinearity diagnostic and dropped from the ML feature set.

Selection criterion

{{ analytics.selection_criterion }}

Why accuracy alone is insufficient here. The base rate is {{ '%.1f'|format(100 * metadata.class_balance) }}% late, so a model that predicted "late" for every order would score {{ '%.1f'|format(100 * metadata.class_balance) }}% accuracy while being useless for deciding anything. Accuracy also hides which kind of error the model makes, and the two are not equally costly — see the confusion matrix on the diagnostics page.

Model performance

The four models land within 0.03 AUC of each other, and a depth-capped decision tree is competitive with gradient boosting. That is itself informative: the underlying relationship is close to a four-way lookup on shipping mode, so there is little non-linear structure for a more flexible learner to exploit.

Baseline and decision-support models

Baseline model

Includes the historically chosen Shipping Mode as an observed feature. This is the honest forecasting model: it answers "given how this order is actually being shipped, how likely is it to be late?"

Decision-support model

The same fitted model, queried counterfactually: each order is re-scored with every shipping mode substituted in, and the results feed the decision engine.

This is not a causal estimate. Shipping-mode assignment here is observational, so substituting a mode gives a model-implied scenario, not a prediction of what would happen if management actually switched. Results are labelled that way throughout the simulator.
