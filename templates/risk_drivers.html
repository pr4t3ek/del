Permutation importance

Drop in held-out ROC-AUC when the feature is randomly shuffled — the honest measure, computed on data the model never saw

Reading this chart

Permutation importance is measured on the held-out set, so a feature that the model merely memorised scores zero. It is preferred here over tree impurity importance, which is biased toward high-cardinality features — and this dataset has several (Order City has 3,597 levels before bucketing).

{% set top = imp.permutation[0] %} {% set second = imp.permutation[1] if imp.permutation|length > 1 else none %}

One driver, then nothing. {{ top.feature }} costs {{ '%.4f'|format(top.importance) }} AUC when shuffled. {% if second %}The next feature, {{ second.feature }}, costs {{ '%.4f'|format(second.importance) }} — {% if second.importance > 0 %}roughly {{ '%.0f'|format(top.importance / second.importance) }}x smaller{% else %} effectively nothing{% endif %}.{% endif %}

Near-zero importance is a real result, not a missing one. Market, region, country, category, customer segment, order size, discount and network load genuinely carry no delay signal in this dataset. The statistical tests reach the same conclusion independently: every one of those factors returns a negligible effect size and fails to survive multiple-testing correction.

Association, prediction, causation, scenario

Statistical association

Shipping mode and late delivery move together in the historical record. Established by the chi-square test (Cramer's V = {{ '%.3f'|format(analytics.statistics.results[0].effect_size) }}).

Model prediction

Given an order's mode and characteristics, the model outputs a probability of late delivery. Validated on held-out data at {{ '%.3f'|format(analytics.model_comparison[analytics.best_model].roc_auc) }} AUC.

Causal claim — not made

Mode assignment here is observational, not randomised. Nothing on this page claims that switching a mode causes the historical difference in late rate.

Decision scenario

Substituting a mode and re-scoring produces a model-implied scenario: what the model expects for an order with those characteristics, under stated assumptions.
