Why {{ s.n_tests }} factors, when the model uses {{ metadata.features|length }} features?

These are two different questions

The {{ metadata.features|length }} model features are not {{ metadata.features|length }} independent business factors. Several are different encodings of the same underlying variable, and some cannot support a valid hypothesis test at all:

  • Encodings of one variable. month_sin and month_cos are a single factor — order month — written as two columns. Testing them separately would count it twice.
  • Components of a tested factor. Latitude and Longitude feed distance_km, which is tested. On their own they are coordinates, not a business factor.
  • Too sparse for the test to be valid. Order City has 3,597 levels. A chi-square across them would leave most cells in single digits and violate the test's assumptions, so destination is tested at Market, Order Region and Order Country level instead.
  • Multiple-testing cost. Every additional test raises the correction threshold the whole family must clear, which would hide a genuine effect rather than reveal one.

The model still looked at all of them

The hypothesis tests are not the only evidence. The feature ablation on the Classification page feeds every one of the {{ analytics.ablation.without_mode.n_features }} non-mode features simultaneously — all the geography, all the calendar features, distance, network load, order composition — into gradient boosting, including any interaction between them.

It reaches {{ '%.3f'|format(analytics.ablation.without_mode.metrics.roc_auc) }} AUC. Chance is 0.500.

So a model that saw all {{ analytics.ablation.without_mode.n_features }} features together, and could exploit any combination of them, found almost nothing. That covers the columns these {{ s.n_tests }} tests do not individually reach.

Every column in the original file is accounted for in the predictor-availability table on the Classification page — what was used, what was not, and why.

Method. {{ s.note }}

Significance level α = {{ s.alpha }}. Because {{ s.n_tests }} tests are run on one dataset, p-values are corrected with the {{ s.correction }} procedure to control the false discovery rate. Numeric factors use Mann-Whitney U rather than a t-test: order value, profit and discount are heavily skewed, so the normality assumption does not hold.

Effect size, not just p-value

Effect size by factor

Cramer's V for categorical factors, rank-biserial r for numeric

Why the ranking is by effect size

At {{ '{:,}'.format(s.n_orders) }} observations, a hypothesis test detects differences far smaller than anything a planner could act on. A p-value answers "is this difference distinguishable from zero?", not "is it big enough to matter?"

The table below reports both. Read the effect-size column first: a factor with p < 0.001 and Cramer's V of 0.02 is a statistically real but operationally irrelevant difference.
